# Repository and Host Map

This file answers one question: **what goes where?**

`project-QQ` is the control repo you can hand to a new agent so it understands the project and knows which execution prompt to run. The implemented system later separates infrastructure code from knowledge content.

## 1. `sorensadrgit-art/project-QQ` — project control repo

Keep here:

```text
README.md
REPO_MAP.md
PLAN.md
ARCHITECTURE.md
CONTRACTS.md
DECISIONS.md
EXECUTION_ORDER.md
KNOWLEDGE_STANDARDS.md
INGESTION_CHECKLIST.md
RECOVERY.md
REFERENCES.md
VERIFICATION.md
prompts/
  01_foundation_and_repo_governance.md
  02_agent_browser_installation_and_mcp.md
  03_qdrant_knowledge_platform_and_github_sync.md
  04_hermes_integration_and_operating_rules.md
  05_knowledge_ingestion_and_update_workflow.md
```

Purpose: project instructions, architecture, recovery knowledge, and cold-start prompts. A future agent can begin here without this ChatGPT conversation.

Do **not** put browser authentication state, Qdrant storage, secrets, or the long-term Spline/GSAP/React/WebGL corpus here.

## 2. Prompt 01 — run on the control/development machine

File:

```text
prompts/01_foundation_and_repo_governance.md
```

Run this first on a machine with Git and preferably authenticated GitHub access.

It creates or normalizes two operational repositories:

```text
hermes-platform
hermes-knowledge
```

### `hermes-platform`

This becomes the canonical repo for executable infrastructure and integrations:

```text
infra/agent-browser/
infra/qdrant/
services/knowledge-indexer/
services/knowledge-gateway/
integrations/hermes/
tools/knowledge-ingestion/
docs/runbooks/
.github/workflows/
```

### `hermes-knowledge`

This becomes the canonical repo for actual technical knowledge:

```text
sources/spline/
sources/gsap/
sources/react/
sources/webgl/
normalized/spline/
normalized/gsap/
normalized/react/
normalized/webgl/
manifests/sources.jsonl
tests/retrieval_cases.yaml
KNOWLEDGE_STANDARDS.md
INGESTION_PLAYBOOK.md
```

Once `hermes-knowledge` exists, future technical data belongs there—not in `project-QQ`.

## 3. Prompt 02 — run on the browser/Hermes host

File:

```text
prompts/02_agent_browser_installation_and_mcp.md
```

Run on the machine where Agent Browser will actually drive a browser. In the normal desktop setup this is the same machine that runs Hermes Desktop/CLI.

It installs/configures:

```text
agent-browser CLI
Chromium/Chrome runtime
Agent Browser MCP stdio wrapper
browser verification scripts
encrypted restore-session configuration
```

Host-local only; never commit:

```text
~/.config/hermes-platform/agent-browser.env
~/.config/hermes-platform/agent-browser/states/
~/.config/hermes-platform/agent-browser/profile/
browser cookies/localStorage/session material
AGENT_BROWSER_ENCRYPTION_KEY value
```

The source-controlled wrapper/scripts generated by this prompt belong in `hermes-platform/infra/agent-browser/`.

## 4. Prompt 03 — run on the knowledge VPS

File:

```text
prompts/03_qdrant_knowledge_platform_and_github_sync.md
```

Run on the VPS that will host the retrieval backend.

It installs/configures:

```text
Qdrant
knowledge-indexer
knowledge MCP gateway
atomic Qdrant publish/rollback
snapshots
GitHub push trigger
VPS reconciliation timer
```

Source-controlled implementation belongs in `hermes-platform`.

Actual persistent runtime data stays on the VPS, for example:

```text
/var/lib/hermes-kb/qdrant/
/var/lib/hermes-kb/snapshots/
/var/lib/hermes-kb/embedding-cache/
/var/lib/hermes-kb/builds/
```

Secrets stay on the VPS, for example:

```text
/etc/hermes-kb/qdrant.env
/etc/hermes-kb/gateway.env
/etc/hermes-kb/sync.env
```

Those files must never be pushed to GitHub.

## 5. Prompt 04 — run on the Hermes host/Desktop

File:

```text
prompts/04_hermes_integration_and_operating_rules.md
```

Run where Hermes Agent/Hermes Desktop is installed.

It connects Hermes to:

```text
Agent Browser MCP   → local stdio
Knowledge MCP       → private/TLS/SSH-tunneled VPS endpoint
```

It also installs the source-controlled routing skills under:

```text
hermes-platform/integrations/hermes/
```

Hermes host-local config/secrets remain local:

```text
~/.hermes/config.yaml
~/.hermes/.env
```

The real `KNOWLEDGE_MCP_BEARER_TOKEN` stays in `~/.hermes/.env`; it is referenced by environment substitution from Hermes config and never committed.

## 6. Prompt 05 — run from an authorized knowledge-development environment

File:

```text
prompts/05_knowledge_ingestion_and_update_workflow.md
```

Run on a machine/agent that can access:

```text
hermes-platform
hermes-knowledge
GitHub
and, for full publication verification, the knowledge VPS/gateway
```

It creates the reusable ingestion tooling in:

```text
hermes-platform/tools/knowledge-ingestion/
```

and maintains knowledge-governance/content files in:

```text
hermes-knowledge/
```

After this phase, the normal future workflow is:

```text
new data
→ sources/{domain}/
→ normalize/validate
→ normalized/{domain}/
→ commit to hermes-knowledge
→ GitHub validation
→ VPS atomic publish to Qdrant
→ retrieval verification
```

You should then be able to hand a future agent new data and tell it to follow `INGESTION_PLAYBOOK.md`.

## Memory location

Do not place large technical corpora in Hermes memory.

Use:

```text
Hermes durable memory → small stable personal/project preferences and decisions
Hermes skills         → procedures/routing behavior
hermes-knowledge Git  → canonical technical knowledge
Qdrant                → derived searchable index of that knowledge
project-QQ            → project-control documentation and execution prompts
```

## Security boundary — never commit

Never commit any of the following to `project-QQ`, `hermes-platform`, or `hermes-knowledge`:

```text
passwords
2FA/recovery codes
API keys
Qdrant admin/API keys
KNOWLEDGE_MCP_BEARER_TOKEN values
AGENT_BROWSER_ENCRYPTION_KEY values
browser cookies/storage state/profiles
SSH private keys
populated .env files
Hermes ~/.hermes/.env
private authenticated browser screenshots containing secrets
```

Commit only `.env.example` or equivalent files with variable names and empty/sample-safe non-secret values.

## Recovery rule

If an agent loses context, start with:

```text
project-QQ/README.md
project-QQ/REPO_MAP.md
project-QQ/EXECUTION_ORDER.md
project-QQ/DECISIONS.md
```

Then inspect the `docs/handoffs/` files produced inside `hermes-platform` to determine which phases have actually passed on real hosts.

Do not infer runtime completion merely because a prompt exists in GitHub.
